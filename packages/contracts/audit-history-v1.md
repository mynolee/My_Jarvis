# Audit history read-only contract v1

GET /api/v1/audit returns the authenticated owner's sanitized audit metadata. Success uses the existing `{data, request_id}` envelope; `audit-history-response.schema.json` describes data. It does not perform execution, cancellation, approval, retry, reconciliation, notification-open, model inference or provider access. A read remains available while execution is paused, subject to current owner-session authentication. This slice is neither a complete execution-detail report nor real-provider verification.

## Query and authority

Optional query fields are `scope`, `limit` and `cursor`, each appearing at most once. The scope is ALL by default or RUNS. ALL includes each owner audit row, sanitizing unknown event types. RUNS includes only the explicit RUN event allowlist. It is not a filter on current status: terminal and nonterminal run events can appear together. No owner, project, run, status or event-type query is accepted.

The page size defaults to 20 and is bounded to 1..100. On the wire `limit` is a canonical positive decimal string: no whitespace, signs, decimal points, exponent, leading zero or blank value. An omitted cursor begins a new traversal. Empty, duplicated or unknown parameters, a body, invalid scope/limit, or a query value longer than 1024 characters return 400 INVALID_REQUEST through the existing error envelope. A nonempty bounded cursor with malformed syntax/encoding, invalid integrity or wrong binding returns 400 INVALID_CURSOR. An otherwise valid authenticated cursor whose lifetime has elapsed returns 410 AUDIT_CURSOR_EXPIRED. `audit-history-query.schema.json` describes the unique-value query projection; HTTP must additionally reject duplicate fields and bodies before that projection can hide them.

Owner identity is derived from the authenticated session, never caller input. Revalidate the owner, session revocation, session lifetimes and security epoch within the same repeatable-read, read-only transaction as each page. An absent/expired session is rejected by existing middleware as 401 AUTHENTICATION_REQUIRED; a revoked or stale session found at service revalidation returns 401 SESSION_REVOKED. Database failure or corrupt stored metadata must produce sanitized 500 INTERNAL_ERROR, not a successful empty page. No recent reauthentication is needed for this read. The read model makes no domain writes; existing authentication middleware may update the session's last-seen timestamp. Return Cache-Control: no-store and the existing security headers. A concurrent revocation after the page snapshot is not serialized against response delivery.

## Page, ordering and cursor

Data has exactly `checked_at`, `scope`, `items` and `next_cursor`. The database observation time is `checked_at`. All timestamps are actual UTC instants with Z and up to six fractional digits; years are 0001..9999. UUIDs are canonical lowercase strings. Strings and JSON values must obey the existing Unicode/strict JSON contract. These metadata remain private data despite excluding content.

Events are sorted by happened_at descending, then UUID descending, comparing instants at full microsecond precision. A following page applies a strict tuple boundary `(happened_at,id) < (previous_last_happened_at,previous_last_id)`. Ties use UUID byte order, equivalent to canonical UUID string order. The server fetches at most limit+1 rows; items contains at most limit, and next_cursor is non-null only when another row remains. There is no cursor for an empty page. There are no duplicate event IDs within a page. Do not deduplicate distinct events merely because they reference the same resource or run.

The cursor is opaque and is not an authority token. It is an authenticated, canonical base64url token with a dot-separated 43-character signature, at most 1024 characters. Its integrity binds the endpoint/version, owner, scope, originating session, security epoch, tuple boundary and a database-clock-issued 15-minute traversal lifetime. Every continuation retains the original issue/expiry time; fetching another page does not renew it. The session binding does not expose the session token/hash. Expiry equality is expired. A changed owner, session, epoch or scope, tampering, malformed encoding or invalid cursor contents fails closed as INVALID_CURSOR. An otherwise valid cursor with checked_at at or after its expiry fails as AUDIT_CURSOR_EXPIRED. Neither error echoes the token. Session authentication is independently revalidated on every page. A page-size change does not expand owner or scope. Clients must neither interpret nor synthesize cursors. Restart with a fresh first-page request after expiry or scope/session change.

Each page observes a fresh database snapshot. The ordering is stable keyset pagination, not frozen membership or a frozen current-state snapshot across several requests. Later inserts above the boundary are absent from remaining pages until refresh; a later/backdated insert below the boundary can appear in a later page. A current run state can change between pages even when the same run appears in both. Do not claim a complete point-in-time export, a full event history, gap-free transaction snapshot or verification history from this bounded read model.

## Closed event projection

Each item has exactly `id`, `event_type`, `happened_at`, `resource_kind`, `resource_id` and `run`. `id` is the audit event identity. The exact event-to-kind allowlist is in `fixtures/audit-history/event-kinds.json` and the item/response schemas. Classification uses exact strings, never a prefix or guessed UUID join. In particular:

- APPROVAL_CONSUMED and APPROVAL_REJECTED refer to RUN, not an approval row.
- TASK_INTENT_* refers to TASK_INTENT, not TASK.
- MEMORY_INTENT_ISSUED and MEMORY_DELETE_PREPARED refer to MEMORY_INTENT and MEMORY_DELETE_PREPARATION respectively.
- SCHEDULE_PREPARED refers to SCHEDULE_PREPARATION. The confirm/disable events refer to SCHEDULE.
- REMINDER_PLANNED, REMINDER_BLOCKED, REMINDER_SKIPPED_MISSED and REMINDER_CANCELLED refer to SCHEDULE_OCCURRENCE.
- REMINDER_INBOX_CREATED and NOTIFICATION_OPENED refer to NOTIFICATION.
- OWNER_CREATED, OWNER_PROFILE_UPDATED and EXECUTION_PAUSED/RESUMED refer to OWNER.

Known event types keep their persisted resource UUID as immutable audit metadata, even if the resource no longer exists. This is not live-resource access authority. For every unknown/future/raw event string, return the literal event_type OTHER and resource_kind OTHER, with resource_id null and run null. Do not return the original event text, even if it resembles a familiar prefix. No payload, raw row, message/body/title, arguments, additional owner_id field, actor/authentication identifier, policy detail, secret, encrypted storage reference, provider result or free-form error may be exposed.

Only explicitly mapped RUN events may have a non-null run. Use an owner-and-ID checked run join. If the run is absent or belongs to another owner, preserve the owned audit reference but return run null and expose no foreign state or link. Never fall back to joining on ID alone. A non-null run has exactly `id` and `current_status`; its id must equal resource_id and status must be one of the existing run-state enum. The run object is the only available navigation target; the server supplies no arbitrary URL. A known non-RUN event always has run null even if its polymorphic resource UUID happens to equal a run UUID.

`current_status` is the run's saved state at this page's checked_at snapshot, not its historical state when the event happened. Event metadata and current state are separate facts. There is no execution_mode, real/verified flag, policy outcome, approval payload, provider account or verification timestamp: those are not explicitly stored in the audit record. SUCCEEDED and MOCK_RECONCILED must never become evidence of a real external provider action. UNKNOWN stays uncertain and does not authorize retries or reconciliation. Execution and verification details need a separately authorized, truthful detail model.

## Client behavior and limits

Render fixed labels and IDs as text. Show event time and the page observation time separately. Current run state must be labelled current, and unavailable run details must be explicit rather than invented. This panel displays times in Korean time (Asia/Seoul, KST) while the wire stays UTC; do not reinterpret UTC strings as local wall time. It exposes no execution, approval, cancel, retry, reconcile or notification-open action.

Keep scope/pagination bounded; reject invalid responses, wrong scope, malformed tuples, bad ordering, duplicate IDs, cross-page overlaps and mismatched run identities. A next cursor requires a full requested page. Use request/session fences and clear private data on logout, session change and disposal. A failed refresh must not relabel stale rows with a newer checked_at. Pages can have distinct checked_at values; do not label earlier page states as refreshed by loading the next page. Reject late responses from a previous session or scope.

The server serializes closed objects with unique keys. The current browser transport parses JSON before object validation, so its validator cannot recover duplicate raw response keys or original numeric spelling. Do not claim raw-wire duplicate-key validation from the browser alone. The synthetic schema/reference checks cover wire projection, explicit mapping, ordering and boundary examples only. They do not prove HTTP authorization, SQL isolation, real cryptographic production cursor behavior, browser rendering, provider outcomes or release acceptance; those need their own executed runtime evidence.
