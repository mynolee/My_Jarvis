# Core M0 candidate

Java 21 / Spring Boot 4.1.1 / PostgreSQL. This is a synthetic-only development candidate, not a production release or a complete security certification.

## Current behavior

- `/api/v1/auth/csrf` creates an anonymous server session; mutations require exact configured Origin plus `X-CSRF-Token`.
- Bootstrap is closed after one owner. A local interactive administrative entrypoint creates a 256-bit token with a 15-minute expiry and five submissions. Only its hash is stored. The owner insert and token consumption are transactional.
- Argon2id uses 19 MiB, two iterations, parallelism one. Passwords are 15–128 Unicode code points, at most 1,024 UTF-8 bytes, without trimming or normalization. Four concurrent hashes at most; account/IP attempts are reserved atomically before hashing. The IP cap includes successful attempts.
- Secure, HttpOnly, SameSite=Lax `__Host-jarvis` cookies; no Domain. Server sessions expire after two idle hours or 12 absolute hours. Login and reauthentication rotate session and CSRF. Recent reauthentication lasts five minutes. Sensitive mutations revalidate the database session under the same owner lock used by logout and rotation.
- Conversations and messages persist. The owner + client message UUID deduplicates identical content; changed content or conversation produces 409. Message text, action snapshots and run results use AES-256-GCM with owner/record/purpose AAD and a database nonce uniqueness ledger. Nonce reservation uses a dedicated maximum-two-connection pool, separate from the maximum-ten business pool. Its bounded transaction commits before encryption and survives business rollback, preserving nonce uniqueness without depending on a connection held by an outer transaction. Conversation titles are currently ordinary plaintext metadata: use synthetic titles only.
- The in-process deterministic mock planner never calls a model or network service. `/calendar` prepares one fixed synthetic Calendar proposal, requiring an approval card. `/calendar-timeout` records one synthetic effect, returns UNKNOWN, and never automatically retries. `/deny`, `/mail`, and `/mail-timeout` are blocked; mail is not registered. Other messages receive a fixed mock answer. `/need-input` demonstrates WAITING_INPUT.
- Approval reads an immutable stored JCS snapshot; the client submits only decision, expected action version and payload hash. One transaction consumes approval, creates the one-time authorization and unique job, and writes audit/outbox. The executor rechecks epoch, pause/cancel, expiry and hash before starting.
- PostgreSQL SKIP LOCKED leases fence stale generations. Started uncertain work becomes UNKNOWN rather than being automatically retried. `/runs/{id}/reconcile` performs read-only verification of an existing synthetic effect. Cancellation never claims an in-flight effect was undone.
- SSE is a finite authenticated event batch with two-second EventSource reconnection. The UUID Last-Event-ID must belong to the same owner and conversation. This is not a persistent streaming connection implementation.

## Start locally

Supply a PostgreSQL database and a private mounted 32-byte encryption key file with owner-only permissions. Keep the key outside the repository. Required settings are `JARVIS_DB_URL`, `JARVIS_DB_USER`, `JARVIS_DB_PASSWORD`, `JARVIS_KEY_FILE`, and `JARVIS_ORIGIN` (exact HTTPS origin). Do not put credentials in the JDBC URL. The server binds loopback port 8080 and does not interpret forwarded headers. Terminate development HTTPS in a local reverse proxy serving Web and `/api/v1` under the same origin; real browser HTTPS cookie behavior must be verified separately.

Run `./gradlew :apps:core:bootRun`. Flyway creates the schema; production migration-role separation is not implemented in this mock candidate. Only `jarvis.mode=mock` is accepted; setting another mode fails startup.

To issue the bootstrap token, run `./gradlew :apps:core:runtimeClasspathFile`, then `java -cp "$(cat apps/core/build/runtime-classpath.txt)" dev.myjarvis.core.BootstrapAdmin` from a real local interactive TTY and the same DB environment. The administrator program deliberately refuses redirected/noninteractive output. Gradle's JavaExec may not preserve a console, so use a direct `java -cp ... dev.myjarvis.core.BootstrapAdmin` invocation when it does not. No public HTTP endpoint issues tokens. Generate the private encryption key separately with a cryptographic random source. Never send keys or bootstrap tokens to a model, URL, log or commit.

## Tests and honest scope

`./gradlew :apps:core:test` starts an ephemeral PostgreSQL **17.11** through the enforced embedded-postgres binaries BOM. The integration fixture asserts the actual server major version is 17. Compatibility is not claimed until that suite executes successfully. The written integration suite covers bootstrap races, rate reservations, sessions, strict JSON, JCS vectors, deduplication, owner-matched foreign keys, approval tamper/concurrency/rollback, UNKNOWN reconciliation, cancellation, lease fencing AAD, exhausted-business-pool nonce allocation, twenty concurrent message accepts, and nonce persistence after rollback. A written test is not a passing test; inspect actual Gradle XML/HTML results.

On the initial restricted development machine, Maven/plugin resolution and the escalated tool sandbox were unavailable. Full Gradle and database test execution therefore remained NOT_RUN at the initial checkpoint. A separate Java-only probe actually exercised the shared three JCS vectors plus nine strict-input rejections against available Jackson jars. A compile-only Argon2 signature stub was used outside this repository only to check Java syntax, never to run authentication or integration tests. It is not part of the build or a substitute for real compilation/testing.

Not implemented/enabled: typed intents or reusable grants, real Calendar/mail writes, verified end-to-end real-model inference, uploads, OAuth, device commands, training, external data egress, production key rotation, audit hash checkpoints, monetary provider budget accounting, persistent SSE caps, production restore/recovery procedures, and release scanning/attestation. Mock Calendar uses stricter individual approval instead of granting reusable R2 authority. There is no arbitrary execute-tool endpoint. Do not enable missing features on the strength of mock tests.

## Optional v4 local text inference candidate

The mock conversation route stays explicit and unchanged. A separate authenticated, CSRF-protected `POST /api/v1/conversations/{id}/local-inference` accepts only `client_message_id` and `text`. `GET /api/v1/local-model/status` reports only a safe mode/model identifier/readiness; no private path or certificate detail is returned. Local and mock runs are distinguished by `execution_mode`. Local UNKNOWN cannot use the mock reconciliation endpoint.

Local inference is disabled by default. Enable only with private, owner-readable mounted TLS client certificate/key, trusted CA and Ed25519 signing key, and the exact approved model manifest hash. Configure `JARVIS_LOCAL_ENABLED`, `JARVIS_LOCAL_URL`, `JARVIS_LOCAL_MANIFEST_HASH`, `JARVIS_LOCAL_CLIENT_CERT_FILE`, `JARVIS_LOCAL_CLIENT_KEY_FILE`, `JARVIS_LOCAL_CA_FILE`, `JARVIS_LOCAL_SIGNING_KEY_FILE`, and `JARVIS_LOCAL_SIGNING_KEY_ID` in ignored `.env` or the approved local launcher. Never commit populated environment files, private keys, certificates identifying the user, or actual model paths. Keys use unencrypted PKCS8 PEM in owner-only files. HTTPS is loopback-only, TLS 1.3 with client certificate authentication and server hostname/CA validation; redirects are disabled.

The capability signs canonical JSON with Ed25519 and binds owner, audience, request/run/reservation, exact request hash, output ceiling, nonce and at most 60 seconds expiry. Transport sends one request and never retries. Response size and full response completion time are bounded. Readiness requires authenticated transport, matching model/manifest and strict boolean integrity/runtime evidence. It does not imply that real inference or the integrated product has been verified.

PostgreSQL reserves one 60-second computation and at most 512 output tokens per run, at most two queued/started/UNKNOWN reservations per owner, at most one local worker in this Core process, 3,600,000 ms/day and 36,000,000 ms/month (UTC). Input including model template is capped by Python at 3,584 tokens; output reserves 512, total at most 4,096. There is one model call and no fallback. The daily/monthly caps conservatively count the full reservation even after successful/failed inference. Cancelled-before-start reservations are released. Ambiguous or interrupted started work retains UNKNOWN and its full reservation; operators need separate evidence-based recovery before it can be reclaimed. These are local resource caps, not monetary billing estimates.

Cancellation/pause interrupts active HTTP calls; Python must observe disconnect and terminate its worker. Started work remains UNKNOWN rather than claiming rollback. Stale STARTED rows become UNKNOWN after 90 seconds; they are never requeued after restart. Only strictly validated ANSWER/NEED_INPUT/ERROR responses are accepted; proposal/tool outputs cannot create authority. Results remain AES-GCM encrypted and owner/run bound. Model error codes are preserved as safe text, without raw service errors or prompts.

For same-origin packaging, first build `apps/web`, then invoke `:apps:core:packageWeb :apps:core:bootJar`. Set `JARVIS_WEB_ENABLED=true` only when serving the packaged static app. Spring HTTPS requires the private configured `SERVER_SSL_CERTIFICATE` and `SERVER_SSL_CERTIFICATE_PRIVATE_KEY`; use the approved local launcher. Static access is allowlisted to the root index and safe built asset names, with a restrictive same-origin CSP.
